# file muncher · 文件阿呜

**把多余的文件，喂给桌面上的小家伙。**

文件阿呜是一款离线运行的 macOS / Windows 桌面文件与文件夹删除器。把文件拖给宠物，它会用自己的方式吃掉文件；关掉主窗口后，小家伙仍会留在桌面上，陪你整理文件。

默认删除方式是**移入系统回收站**。动画用于反馈真实处理结果，只有成功处理的文件才会计入成长记录。

## 功能

- **拖放投喂**：支持多个文件和文件夹，也可用文件选择器操作；目录内文件递归统计。
- **五款原创造型**：每款都有不同的外形、待机、处理、点击与拖动动画，可直接试播，试播不会删除文件。
- **桌面悬浮宠物**：拖动身体改变位置，朝移动方向做动作，松手轻轻落地；点击也有回应。
- **实时调整大小**：右键宠物或在主窗口设置中调整到 50%–100%。独立大小面板放在旁边，调整时能看清宠物。
- **一个气泡就够**：悬停显示吃掉的文件数、总大小和虚拟体重；吃完的反馈优先显示两秒，再恢复悬停信息或隐藏。
- **成长有上限**：成功投喂会增加统计和体重，成长倍率最多为初始体型的 1.3 倍，不会无限占据桌面。
- **目光跟随**：宠物会看向光标；小坦克会瞄准拖来的文件，待命时显示 `stand by !`，成功处理后开炮。
- **本地保存**：造型、大小、偏好与成长记录保存在本机；不需要账号，不上传文件内容或名称。

## 使用方式

1. 在主窗口选择造型，将文件或文件夹拖入中央舞台，或拖给桌面宠物。
2. 默认移入回收站，可通过系统回收站恢复。需要永久删除时，在设置中切换，每一批仍需系统确认。
3. 右键宠物调整大小、重开主窗口、隐藏宠物或退出；macOS 也支持 Control+单击，键盘支持 Shift+F10。
4. 关闭主窗口只会收起主界面。要彻底退出，请使用托盘菜单的“退出”，或在 macOS 按 Command+Q。

普通永久删除不等于磁盘安全擦除，不保证数据无法恢复。回收站失败不会自动改为永久删除；失败和部分成功会明确显示。软件保护系统、用户主目录、应用及数据目录，符号链接只处理链接本身。完整边界见 [产品与技术设计](docs/design.md)。

## 本地开发：无需安装包

环境：**Node.js 24、npm**；运行桌面版需要图形桌面环境。浏览器回归测试另需安装 Google Chrome。

进入仓库根目录后首次执行：

```sh
npm ci
```

macOS / Linux shell：

```sh
export FILE_MUNCHER_USER_DATA="$PWD/.local-data/development"
npm start
```

Windows PowerShell：

```powershell
$env:FILE_MUNCHER_USER_DATA = Join-Path (Get-Location).Path '.local-data/development'
npm start
```

`npm start` 编译源码并启动 Electron，**不会生成安装包，也没有自动热更新**。修改后正常退出开发版，再运行一次即可。独立配置目录只隔离设置和成长记录，文件删除仍然真实执行；调试时只投喂自己创建的测试文件。

只想看造型或动画，可运行 `npm run preview`，打开 `http://127.0.0.1:4173`。浏览器预览不执行真实文件操作。

## 项目结构

```text
src/main/       Electron 主进程、文件处理、窗口管理、持久化和 preload
src/renderer/   主窗口、桌面宠物、五款 SVG/CSS 动画与交互
src/shared/     类型定义、成长规则、窗口布局与目光计算
tests/          核心行为测试
scripts/        构建、预览、桌面和浏览器回归脚本
assets/         应用图标
docs/           产品设计、开发调试说明与验收记录
.github/        发布构建工作流
```

技术栈为 Electron、TypeScript、esbuild 和 electron-builder，沿用 npm 管理依赖；无需另装动画框架或服务端。

## 安装与发布

安装包是发布产物，不纳入 Git 仓库。只有准备发布或验证安装行为时才执行 `pack:*`；普通功能修改、调试和提交不要求打包。

- macOS：打开对应架构的 DMG，将应用拖入 Applications。
- Windows x64：运行安装程序，按向导安装。
- 本地打包默认输出到 `release/`。现有 GitHub Actions 仅在手动触发或推送 `v*` 标签时打包，普通分支提交不会打包，也不会自动发布 GitHub Release。

当前 Mac 包使用 ad-hoc 签名，尚未配置 Developer ID 签名与公证；Windows 包未作发布者签名。Apple Silicon Mac 已完成桌面验收，Intel Mac 与 Windows 仍需实机验证。正式分发前按 [开发规范中的发布步骤](docs/development.md) 补齐相应验证。
