# file muncher · 文件阿呜

当前产品方案，2026-10-30。

## 产品与范围

一个离线运行的中文桌面文件/文件夹删除器，面向 macOS 和 Windows。核心体验是拖入文件，粉碎机做出有趣反应，完成后准确显示系统处理结果。支持一次拖入多个文件或目录，提供文件选择按钮和不操作真实文件的动画试播。

默认移入系统回收站；设置中可切换永久删除，每批永久删除通过系统对话框再次确认，取消为默认按钮。“粉碎”描述动画体验，首版不承诺磁盘安全擦除或无法恢复。

不加入账号、联网服务、订阅、自动扫描、自动清理、开机启动或后台监控。仅处理用户主动拖入或通过选择器选中的对象。

## 界面

主界面采用轻松的桌面玩具风格，中央大面积动画舞台，侧边陈列五款造型，底部展示本批处理结果。每款主题不仅更换颜色，还拥有不同形状、动作、纸片轨迹与完成反馈。主题与偏好只保存在本机。

独立透明悬浮宠物常驻桌面，与主窗口共用主题、偏好和成长记录。关闭主窗口会显示宠物，宠物可继续接收文件；可通过右键面板、托盘或 Dock 重新打开主窗口。明确点击“退出”才结束应用。按住宠物身体可拖动窗口位置，窗口被限制在屏幕工作区内；超过 4 像素的手势识别为拖动，轻点与 Enter/空格触发独立互动，不调用文件接口或改变成长。五款点击时分别跳跃眯眼、像素挥手、坦克空炮、轨道涟漪和转动手柄。身体拖动时按最近的水平位移切换左/右动作，提起并倾斜，停顿 140ms 后保持悬空，松手播放 350ms 的落地；取消或失焦只清理动作，不触发点击。减少动态时保留静态方向提示。

五款宠物只在窗口收到包含 `Files` 类型的 DOM 拖拽事件后追视目标；普通鼠标移动不触发，窗口外也不轮询全局光标。文件离开窗口、取消或结束拖放后清理追视。坦克的左右目标控制炮台朝向，上下目标控制整个车身前后移动，炮塔始终保持正立；文件进入投喂区显示 `stand by !`，成功处理后才播放击碎动画。

成功处理后累计文件数、逻辑字节数与餐数。真实目录递归统计其文件，符号链接仅计算链接本体，空目录可计一餐但不增加文件数。虚拟体重与成长按数量和大小的对数增长，视觉大小限制为初始的 1.3 倍，用户可独立调整悬浮大小至 50%–100%，默认 70%（210×242 逻辑像素），实际窗口范围为 150×194 至 300×315；增长倍率作用于其中的角色，不无限扩大桌面占用。尺寸随偏好持久化，旧配置升级保留成长记录。悬浮宠物没有上下卡片；悬停时单气泡以第一人称报告文件数、逻辑大小和体重，离开后隐藏。气泡按造型、当前尺寸和成长倍率贴近可见身体上方，对一万以上的文件数使用带“约”的万/亿单位；主窗口保留精确计数，避免最小尺寸下长数字遮住角色。成功喂食气泡优先显示两秒，之后若仍悬停恢复统计，否则隐藏；普通成功不保留结果卡，错误和警告仍保留直到用户收起。右键打开 260×180 独立大小面板，贴近当前可见身体，并根据屏幕空余位置避让身体和气泡。滑块 input 即发送尺寸变更，主窗口同样实时生效；按住滑块时面板保持原位，松手且保存完成后重新定位。点击面板外部或关闭按钮均会等待进行中的保存完成后收起，失败则保留面板和错误提示；操作面板内部不会将其关闭。品牌名为 file muncher，中文名为文件阿呜。应用身份不变，并显式沿用 appData 下的原“文件粉碎机”数据目录；统计与偏好原子写入本机状态文件，不保存被删除文件的名称历史。另一窗口的新状态不能被旧动画结果回退。

空闲、拖入预备、处理中、成功、部分失败、失败分别呈现。处理中显示明确状态，慢操作循环动画中段，不能用固定动画时长伪造删除成功。处理期间不切换主题或重复提交，新的文件拖放给出可理解的提示。

提供键盘操作、可见焦点、适合中文的系统字体，以及遵循系统减少动态效果偏好的简化反馈。试播与真实删除严格分离。

## 技术方案

采用 Electron + TypeScript，界面使用本地原创 SVG/CSS，不为每个主题额外引入动画引擎。Electron 主进程负责系统文件操作，沙箱渲染进程仅负责视图与动画，通过窄 preload 接口通信。独立大小面板不能调用文件准备、选择、删除或宠物移动接口。使用 electron-builder 生成安装产物。

备选 Tauri 安装包更小，但需要 Rust 原生构建链与不同系统 WebView 适配；两套原生应用维护成本更高，均不作为首版推荐。

## 文件处理边界

- 主进程验证调用来源和输入路径，只接受真实本地文件、目录及受支持的链接。
- 保护根目录、用户主目录、系统目录、应用自身及其数据目录。
- 去重同一对象；同批的真实父目录和子项只处理一次；符号链接不当成真实父目录。
- 最终一级符号链接只处理链接本体，不能跟随它删除目标。
- 预检后使用一次性批次标识执行，执行前检查对象身份，避免重复操作或明显的路径替换。
- 回收站操作失败绝不自动回退为永久删除；批次逐项报告结果。
- 不读取文件正文，不上传文件名或路径，不保留长期删除记录。
- 每次最多拖入 200 项，每轮递归预检最多 100,000 个条目、10 秒；超出时明确提示拆分，不静默漏计。
- 永久删除目录可能在文件系统报错前部分完成，此时明确提示检查剩余内容，该失败目录不计入成功统计。路径 API 的复核不能替代操作系统级原子整树删除。

## 验证与交付

核心测试覆盖临时文件和非空目录、Unicode 名称、重复项与父子项、符号链接、受保护路径、对象替换、重复提交、部分失败。所有删除验证只使用本任务创建的临时样本。

界面检查覆盖五款独立动画、试播不调用删除、真实结果与动画状态一致、键盘操作和减少动态效果。

交付源码、运行与构建命令、可生成的平台安装包和跨平台 CI 配置。分别记录源码检查、安装包构建、实际启动、平台安装体验、签名/公证状态；没有 Windows 环境时不得把交叉构建当成 Windows 实机验收。

本机当前为 Apple Silicon macOS，有 Node/npm 与 Apple 命令行工具，无有效 Developer ID 代码签名身份。Mac 包使用 ad-hoc 签名用于试用，正式对外发行的 Developer ID 签名和公证需要发布者证书；Windows 安装包同样未作发布者签名。
